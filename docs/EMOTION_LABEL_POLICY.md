# 감정 라벨 체계 검토

## 현재 모델 라벨

현재 로컬 감정 모델의 `config.json` 기준 라벨은 다음 6개입니다.

| index | label |
| ---: | --- |
| 0 | 기쁨 |
| 1 | 놀람 |
| 2 | 분노 |
| 3 | 불안 |
| 4 | 상처 |
| 5 | 슬픔 |

이 라벨 체계는 코드에서 임의로 새로 만든 것이 아니라, 학습된 모델의 `id2label` / `label2id`와 일치해야 하는 값입니다.

## 외부 근거와 도메인 해석

이 프로젝트의 6라벨은 한국어 감정 데이터셋에서 자주 쓰이는 감정 체계와 가깝습니다.

- AI Hub 감성대화 말뭉치 계열은 `기쁨`, `당황`, `분노`, `불안`, `상처`, `슬픔` 라벨 구성을 사용합니다.
- AI Hub 감성 및 발화 스타일별 음성합성 데이터도 `기쁨`, `슬픔`, `분노`, `불안`, `상처`, `당황`, `중립`에 가까운 감정 축을 둡니다.
- KOTE처럼 더 세분화된 한국어 감정 데이터셋은 40개 이상의 세부 감정을 두고, 필요에 따라 더 큰 범주로 매핑할 수 있습니다.

따라서 현재 6분류 자체는 한국어 감정 인식 프로젝트에서 설명 가능한 선택입니다.

다만 현재 모델은 원본 계열에서 자주 쓰이는 `당황`이 아니라 `놀람`으로 저장되어 있습니다. 이는 실수가 아니라 프로젝트 도메인에 맞춘 재명명입니다. GeoMemo는 상담형 대화보다 사용자의 일기/메모에 가까운 짧은 기록을 다루므로, `당황`이라는 사회적·상황적 뉘앙스보다 `놀람`이 사용자가 직접 기록하는 감정 표현에 더 자연스럽다고 판단했습니다.

포트폴리오에서는 다음처럼 설명하는 것이 안전합니다.

> 모델은 한국어 감정 데이터셋에서 자주 쓰이는 `기쁨/당황/분노/불안/상처/슬픔` 계열의 6개 감정 범주를 참고했다. 다만 GeoMemo가 일기형 메모 서비스를 지향하기 때문에, 사용자에게 더 자연스러운 표현인 `놀람`으로 `당황` 계열 라벨을 재명명해 사용했다.

추후 원본 학습 데이터 또는 당시 전처리 노트를 찾으면, `당황`에서 `놀람`으로 바꾼 기준과 예시 문장을 함께 보강하면 좋습니다.

## 현재 평가 결과

남아 있는 로컬 평가 리포트 기준:

- 6-class Accuracy: `0.9002`
- 6-class Macro-F1: `0.9020`
- 2-class Macro-F1: `0.9962`

따라서 “모델이 6개 라벨을 구분할 수 있는가”에 대해서는 최소한 로컬 평가 기준으로 긍정적인 근거가 있습니다.

## 확인해야 할 설계 질문

라벨 체계 자체보다 더 중요한 질문은 서비스에서 이 라벨을 어떻게 해석할지입니다.

### 1. 놀람은 긍정인가?

현재 모델 차원에서는 `기쁨`, `놀람`을 긍정 그룹으로 묶고, `분노`, `불안`, `상처`, `슬픔`을 부정 그룹으로 묶습니다.

이 결정은 단순하고 2-class 평가 결과도 좋지만, `놀람`은 문맥에 따라 긍정, 부정, 중립 모두가 될 수 있습니다.

예시:

- 긍정적 놀람: “생각보다 풍경이 좋아서 놀랐다.”
- 부정적 놀람: “갑자기 큰 소리가 나서 놀랐다.”
- 중립적 놀람: “예상과 달라서 놀랐다.”

따라서 추천/인사이트 로직에서 `놀람`을 `기쁨`과 같은 강한 긍정으로 다루는 것은 과한 해석일 수 있습니다.

### 2. 추천 로직에는 discrete label보다 valence가 더 적합할 수 있다

추천에서는 세부 라벨 이름보다 사용자의 현재 정서 방향과 강도가 더 중요합니다.

공통 감정 정책 모듈 `ai/emotion_policy.py`는 다음과 같은 valence 값을 사용합니다.

| label | valence |
| --- | ---: |
| 기쁨 | 1.0 |
| 놀람 | 0.2 |
| 분노 | -0.9 |
| 불안 | -0.6 |
| 상처 | -0.7 |
| 슬픔 | -0.8 |

이 방식은 `놀람`을 약한 긍정 또는 혼합 감정에 가깝게 처리할 수 있어, 단순한 긍정/부정 이분법보다 안전합니다.

## 현재 정책

포트폴리오 정리 단계에서는 모델 라벨 6개를 유지합니다.

- 모델 호환성을 깨지 않기 위해 라벨 이름과 index를 유지합니다.
- 감정별 stage1, valence, 긍정/부정 판단은 `ai/emotion_policy.py`에서 한 곳에 모아 관리합니다.
- 추천 로직에서는 `놀람`을 `기쁨`과 같은 강한 긍정으로 보지 않고, valence `0.2`를 사용해 약한 긍정 신호로 반영합니다.

## 다음 개선안

1. 원본 학습 데이터 또는 전처리 노트를 찾아 `당황`에서 `놀람`으로 바꾼 기준을 보강한다.
2. `놀람`의 valence를 `0.2`, `0.0`, 또는 문맥 기반으로 나누는 실험을 추가한다.
3. 추천 테스트에 사용자 만족도나 클릭/스크랩 로그 기반의 오프라인 평가 지표를 추가한다.
4. 포트폴리오에는 “모델 라벨을 그대로 쓰는 것”과 “서비스 정책에서 감정을 해석하는 것”을 분리해 설명한다.
