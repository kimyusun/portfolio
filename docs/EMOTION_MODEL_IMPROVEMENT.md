# 감정 모델 개선 계획

## 결론

현재 단계에서 모델 업그레이드는 “바로 교체”보다 “검증 체계부터 세우기”가 먼저입니다.

특히 이 모델은 프로젝트 당시 적절한 공개 도메인 데이터셋을 구하기 어려워 GPT로 만든 합성 데이터를 학습에 활용했습니다. 따라서 기존 로컬 평가 결과가 높게 나왔더라도, 그 수치를 실제 사용자 메모에 대한 최종 성능으로 해석하면 안 됩니다.

현재 모델은 완성된 최종 모델이 아니라 다음을 위한 baseline입니다.

- 팀 프로젝트에서 end-to-end 감정 분석 흐름을 구현하기 위한 baseline
- 추천/인사이트 로직과 감정 라벨을 연결하기 위한 baseline
- 실제 도메인 데이터로 재평가하고 개선할 출발점

합성 학습 데이터 사용에 대한 자세한 기록은 `docs/SYNTHETIC_TRAINING_DATA.md`에 정리했습니다.

## 현재 모델을 유지해도 되는 이유

현재 모델은 최소한 다음 근거를 가집니다.

- 남아 있는 로컬 평가 결과 기준 6-class Accuracy 약 `0.9002`, Macro-F1 약 `0.9020`을 기록했습니다.
- 감정 라벨 체계가 한국어 감정 데이터셋 계열과 연결되어 설명 가능합니다.
- `놀람` 라벨의 도메인 재명명과 추천 정책에서의 약한 긍정 처리까지 문서화했습니다.
- 모델 파일을 공개 저장소에서 분리하고, 모델 없이도 검증 가능한 요청/응답 경계를 테스트할 수 있게 했습니다.

다만 이 근거는 “현재 baseline으로 유지할 수 있다”는 의미이지, “실제 서비스에서도 충분히 검증됐다”는 의미는 아닙니다.

## 왜 추가 검증이 필요한가

합성 데이터로 학습한 모델은 다음 위험을 가집니다.

- 학습 데이터와 평가 데이터가 비슷한 생성 방식이면 점수가 과대평가될 수 있습니다.
- 실제 사용자의 짧고 불완전한 메모 문장에서는 성능이 달라질 수 있습니다.
- 합성 문장은 감정 표현이 명확한 편이라 모호한 실제 문장을 충분히 반영하지 못할 수 있습니다.
- `놀람`, `상처`, `불안`처럼 문맥 의존적인 라벨의 경계가 인위적으로 깔끔해질 수 있습니다.
- confidence score가 높아도 실제 도메인에서는 틀릴 수 있습니다.

따라서 업그레이드 여부는 기존 점수만으로 결정하지 않고, GeoMemo식 도메인 평가셋과 에러 분석으로 판단합니다.

## 2026-05-28 예비 판단

60개 도메인 샘플로 실제 로컬 모델을 CPU 평가한 결과, 전체 Accuracy는 `0.8833`, Macro-F1은 `0.8846`이었습니다. 이 수치는 모델을 즉시 폐기해야 할 정도는 아니지만, 포트폴리오에서 “충분히 검증된 감정 모델”이라고 말하기에는 아직 부족합니다.

라벨별로는 `기쁨`, `놀람`, `분노`, `상처`는 비교적 안정적이었지만, `슬픔`과 `불안` 사이의 혼동이 확인되었습니다.

- `슬픔` recall은 `0.70`으로 가장 낮았습니다.
- `불안` precision은 `0.6923`으로 낮아 다른 부정 감정을 `불안`으로 끌어오는 경향이 있었습니다.
- confidence가 높은 오답도 있었기 때문에 threshold 정책만으로는 모든 오류를 막기 어렵습니다.
- threshold `0.7`을 적용하면 coverage `0.8333`, accepted accuracy `0.92`로 올라가므로 추천/인사이트에서는 낮은 confidence 감정을 약하게 반영하는 현재 정책이 유효합니다.

따라서 현재 판단은 다음과 같습니다.

- 포트폴리오 공개용 baseline으로는 유지할 수 있습니다.
- 실제 서비스 품질을 주장하려면 실제 사용자 메모 또는 사람이 새로 라벨링한 평가셋이 더 필요합니다.
- 모델 보수의 1순위는 전체 교체가 아니라 `슬픔/불안/상처` 경계 사례를 모아 targeted fine-tuning 또는 후보 모델 비교를 진행하는 것입니다.

## 업그레이드가 필요한 신호

다음 중 하나가 확인되면 모델 업그레이드를 검토합니다.

- 일기/메모 문장에서 성능이 눈에 띄게 떨어집니다.
- `놀람`, `불안`, `상처`처럼 문맥 의존적인 라벨의 혼동이 많습니다.
- confidence score가 높지만 실제 예측이 자주 틀립니다.
- 짧은 문장, 은어, 이모티콘, 반어 표현에 취약합니다.
- 추천/인사이트 로직에서 감정 예측 오류가 사용자 경험에 직접 영향을 줍니다.

## 업그레이드 전 먼저 할 일

### 1. 도메인 평가셋 만들기

GeoMemo는 일기형 메모 서비스이므로, 일반 감성 대화 데이터보다 짧은 메모 문장에 가까운 평가셋이 필요합니다.

예시 목표:

- 각 라벨당 최소 30~50개 문장으로 작은 검증셋 구성
- 가능하면 각 라벨당 100개 이상으로 확장
- `놀람`은 긍정/중립/부정 문맥을 나눠 따로 기록
- 사람이 라벨링한 이유를 `note` 또는 `memo`에 남김

현재 샘플은 `data/sample_emotion_domain_eval.csv`에 있습니다.

### 2. 에러 분석 표 만들기

모델이 틀린 문장을 단순히 수치로만 보지 않고 다음 항목으로 기록합니다.

| field | meaning |
| --- | --- |
| `text` | 입력 문장 |
| `true_label` | 사람이 붙인 라벨 |
| `pred_label` | 모델 예측 라벨 |
| `score` | confidence score |
| `error_type` | 라벨 혼동, 문맥 부족, 반어, 중의성 등 |
| `memo` | 개선 아이디어 |

### 3. baseline 재평가

현재 모델을 먼저 같은 도메인 평가셋으로 다시 평가합니다.

확인할 지표:

- Accuracy
- Macro-F1
- per-class F1
- confusion matrix
- confidence calibration
- inference latency

## 업그레이드 옵션

### Option A. 모델은 유지하고 정책만 개선

가장 가벼운 개선입니다.

- confidence threshold 적용
- 낮은 confidence일 때 `unknown` 또는 보수적 처리
- `놀람`을 추천 로직에서 약한 긍정으로 처리
- 인사이트 문장에서 confidence가 낮은 감정은 강하게 단정하지 않기

장점: 빠르고 안전합니다.
단점: 모델 자체의 오류는 줄이지 못합니다.

### Option B. 현재 모델을 도메인 데이터로 추가 fine-tuning

현재 모델 구조를 유지하고 GeoMemo식 메모 문장으로 추가 학습합니다.

장점: 기존 구조와 호환성이 좋습니다.
단점: 사람이 검수한 라벨링 데이터와 학습 환경이 필요합니다.

### Option C. 후보 모델 비교

현재 모델을 baseline으로 두고 다른 한국어 분류 모델과 비교합니다.

비교 기준:

- Macro-F1
- 라벨별 F1
- `놀람`/`상처`/`불안` 혼동률
- 추론 속도
- 모델 크기
- 로컬 배포 가능성

장점: 더 좋은 모델을 찾을 수 있습니다.
단점: 실험 비용이 커지고, 독립적인 도메인 평가셋 없이는 비교 의미가 약합니다.

## 포트폴리오에서의 설명 방식

가장 안전한 설명은 다음과 같습니다.

> 프로젝트 당시에는 서비스 도메인에 맞는 공개 한국어 감정 데이터셋을 확보하기 어려워 GPT 합성 데이터를 활용해 baseline 감정 모델을 만들었다. 기존 로컬 평가에서는 6-class Macro-F1 약 0.90을 기록했지만, 합성 데이터 기반 평가는 실제 사용자 메모에 대한 일반화 성능을 보장하지 않는다고 판단했다. 그래서 모델을 무작정 교체하기보다, 도메인 평가셋과 에러 분석 표를 설계해 현재 모델을 baseline으로 재검증하고 fine-tuning 또는 후보 모델 비교 여부를 판단하는 방향으로 발전시켰다.

## 다음 액션

1. `data/sample_emotion_domain_eval.csv`를 실제 사용자 메모에 가까운 문장으로 확장한다.
2. 현재 모델로 평가를 다시 실행한다.
3. 틀린 예측을 에러 분석 표로 정리한다.
4. confidence threshold와 `unknown` 처리 필요성을 검토한다.
5. 데이터가 충분해지면 fine-tuning 또는 후보 모델 비교를 진행한다.
