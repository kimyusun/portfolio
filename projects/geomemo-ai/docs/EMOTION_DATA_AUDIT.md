# 감정 학습 데이터 점검 기록

## 목적

이 문서는 원본 감정 학습 데이터가 모델 학습에 사용하기에 충분했는지, 그리고 어떤 한계가 있었는지 기록합니다.

원본 파일은 로컬에만 보관합니다.

```text
data/emotion_data.csv
```

이 파일은 실제 학습 데이터이므로 GitHub에 올리지 않습니다. 현재 `.gitignore`의 `data/*.csv` 규칙에 의해 제외됩니다.

## 점검 명령

```bash
python scripts/audit_emotion_data.py --input data/emotion_data.csv --output reports/emotion_data_audit.json
```

`reports/` 폴더도 GitHub에 올리지 않는 로컬 분석 결과 보관 위치입니다.

## 판단

개수만 보면 팀 프로젝트의 baseline fine-tuning 데이터로는 사용할 수 있는 규모입니다. 라벨별 최소 개수가 `508`개이고, 빈 문장이나 빈 라벨이 없으며, 같은 문장이 서로 다른 라벨로 붙은 충돌도 없었습니다.

다만 최종 모델 성능을 주장하기에는 데이터 품질상 한계가 있습니다.

- 문장 길이가 18-60자 사이로 비교적 균일합니다.
- 실제 사용자 메모처럼 아주 짧은 입력, 긴 일기, 오타, 이모티콘, 비문이 거의 반영되지 않았을 가능성이 큽니다.
- 일부 라벨은 감정 키워드 의존 가능성이 있습니다. 예를 들어 `분노`, `불안`은 직접적인 감정 단서가 포함된 문장 비율이 높았습니다.
- 완전 중복이 97개 있어 train/test 분리 전에 중복 제거가 필요합니다.
- GPT 합성 데이터이므로 문장 패턴, 표현 방식, 라벨 경계가 실제 사용자 데이터보다 깔끔할 수 있습니다.

따라서 당시 이 데이터로 모델을 학습한 것은 현실적인 baseline 선택이었지만, 이 데이터만으로 실제 서비스 성능을 보장한다고 말하면 안 됩니다.

## 포트폴리오 설명 문장

> 프로젝트 당시에는 서비스 도메인에 맞는 공개 한국어 감정 데이터 확보가 어려워 GPT 합성 데이터로 baseline 감정 모델을 학습했습니다. 이후 포트폴리오 정리 과정에서 원본 데이터의 라벨 분포, 중복, 문장 길이, 키워드 의존 가능성을 점검했고, 이 데이터가 baseline 학습에는 충분하지만 실제 사용자 메모 성능을 보장하기에는 한계가 있다는 점을 확인했습니다. 그래서 별도 도메인 평가셋과 confidence 정책, 에러 분석 체계를 추가해 모델을 보수적으로 활용하도록 개선했습니다.

## 다음 개선 방향

1. 원본 데이터에서 완전 중복을 제거합니다.
2. train/test 분리 전에 같은 문장 또는 거의 같은 문장이 양쪽에 들어가지 않도록 점검합니다.
3. 실제 사용자 메모와 가까운 짧은 문장, 불완전 문장, 혼합 감정 문장을 별도 평가셋으로 늘립니다.
4. `슬픔/불안/상처` 경계 문장을 더 수집해 targeted fine-tuning 또는 후보 모델 비교에 사용합니다.
5. 모델 성능은 합성 데이터 평가 점수보다 독립 도메인 평가셋 결과를 중심으로 설명합니다.
