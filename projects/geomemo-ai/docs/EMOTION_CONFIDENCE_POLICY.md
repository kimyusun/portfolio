# 감정 예측 신뢰도 정책

## 목적

이 프로젝트의 감정 분류 모델은 초기 baseline이며, 학습 데이터에 GPT 합성 데이터가 포함되어 있습니다. 따라서 confidence score가 높게 나오더라도 실제 사용자의 일기형 메모에서 항상 같은 수준으로 일반화된다고 단정하면 안 됩니다.

이 문서는 낮은 확신 예측을 서비스 로직에서 어떻게 보수적으로 다룰지 정리합니다.

## 기본 정책

- 모델의 원래 예측 라벨은 `emotionLabel`에 그대로 남깁니다.
- confidence score가 기준값보다 낮으면 `safeLabel`을 `unknown`으로 둡니다.
- 기준값은 현재 `0.6`으로 시작합니다.
- `isReliable`은 추천, 인사이트, 에러 분석에서 해당 예측을 강하게 사용할지 판단하는 보조 필드입니다.

예시 응답:

```json
{
  "memoId": 17,
  "emotionLabel": "불안",
  "emotionScore": 0.41,
  "stage1": "부정",
  "valence": -0.7,
  "safeLabel": "unknown",
  "isReliable": false,
  "confidenceThreshold": 0.6
}
```

## 왜 unknown을 두는가

합성 데이터 기반 모델은 다음 상황에서 과신할 수 있습니다.

- 실제 사용자의 짧고 불완전한 문장
- 반어, 농담, 모호한 표현
- `놀람`, `불안`, `상처`처럼 경계가 가까운 라벨
- 감정이 섞여 있거나 맥락이 부족한 일기형 메모

`unknown`은 모델 실패를 숨기기 위한 값이 아니라, 확신이 낮은 예측을 서비스가 그대로 믿지 않게 만드는 안전장치입니다.

## 추천 로직에서의 사용 방향

현재 추천 worker는 감정 라벨과 score를 이용해 장소 점수를 계산합니다. 이후 backend가 `safeLabel` 또는 `isReliable`을 전달할 수 있게 되면 다음처럼 다루는 것이 좋습니다.

- `isReliable = true`: 기존 감정 기반 추천 점수를 정상 적용
- `isReliable = false`: 감정 가중치를 낮추고 장소 긍정 비율, 카테고리 선호, 스크랩 등 행동 기반 신호를 더 크게 반영
- `safeLabel = unknown`: 감정 라벨을 강한 추천 근거 문구로 노출하지 않음

## threshold 조정 기준

`0.6`은 시작값입니다. 실제 기준은 도메인 평가셋과 에러 분석으로 조정해야 합니다.

조정할 때 볼 지표:

- 낮은 confidence 구간의 실제 정답률
- 라벨별 confidence 분포
- `놀람/불안/상처` 혼동률
- 추천 결과에 영향을 준 오분류 사례
- unknown 비율이 너무 높아 서비스 경험을 해치지 않는지

## 포트폴리오 설명 문장

> GPT 합성 데이터로 학습한 baseline 모델의 한계를 인정하고, 예측을 무조건 신뢰하지 않도록 confidence threshold와 unknown 처리 정책을 추가했다. 이를 통해 감정 분석 결과를 추천/인사이트에 연결하되, 낮은 확신 예측은 보수적으로 다루는 방향으로 시스템을 개선했다.
