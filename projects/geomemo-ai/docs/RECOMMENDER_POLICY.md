# 추천 점수 정책

## 현재 점수식의 성격

현재 GeoMemo-AI 추천 점수는 학습된 랭킹 모델이 아니라, 서비스 초기에 사용할 수 있는 해석 가능한 baseline ranking입니다.

즉, “이 공식이 통계적으로 최적이다”라고 주장하기보다는 다음 목적을 가진 휴리스틱으로 보는 것이 정확합니다.

- DB/MQ 없이도 핵심 추천 정책을 테스트할 수 있다.
- 각 점수 항목이 서비스 도메인과 연결되어 있어 설명 가능하다.
- 사용자 로그가 충분히 쌓이기 전에도 기본 추천을 제공할 수 있다.
- 나중에 클릭, 스크랩, 체류 시간 같은 실제 피드백으로 가중치를 검증하고 교체할 수 있다.

## 최종 점수 구성

`ai/recommender/recommender.py`의 기본 가중치는 다음과 같습니다.

| 항목 | 기본 가중치 | 의미 |
| --- | ---: | --- |
| `pos_ratio` | 0.35 | 해당 장소에서 공개 메모가 긍정 감정으로 작성된 비율 |
| `emo_component` | 0.25 | 사용자의 최근 감정과 장소 신호의 조합 |
| `cat_pref` | 0.20 | 사용자가 자주 기록한 선호 카테고리 |
| `scrap` | 0.10 | 사용자가 스크랩한 장소인지 여부 |
| `social` | 0.10 | 팔로우한 사용자의 긍정 반응 수 |

현재 공식은 다음과 같은 선형 결합입니다.

```text
raw_score =
  0.35 * pos_ratio
+ 0.25 * emo_component
+ 0.20 * cat_pref
+ 0.10 * scrap
+ 0.10 * social
```

이후 후보 목록 안에서 `0.3 ~ 0.99` 범위로 min-max 정규화합니다. 이 정규화 점수는 절대적인 품질 점수라기보다, 같은 요청 안에서 후보를 비교하기 위한 표시용 점수입니다.

## 항목별 정당성

### 장소 긍정 비율

GeoMemo는 감정 기반 위치 메모 서비스이므로, 특정 장소가 여러 사용자에게 긍정적으로 기록되었는지는 추천의 핵심 신호가 될 수 있습니다.

특히 최근 감정이 `불안`, `상처`, `슬픔`처럼 부정적인 경우에는 긍정 기록이 많은 장소를 더 우선하는 정책이 서비스 목적과 잘 맞습니다.

### 최근 감정 기반 보정

최근 감정은 장소 추천의 맥락 신호로 사용합니다.

- 부정 감정일 때: 긍정 비율이 높은 장소를 더 강하게 반영합니다.
- 기쁨일 때: 사용자가 원래 좋아하던 카테고리와 긍정 장소 신호를 유지합니다.
- 놀람일 때: 긍정 그룹에 포함하되 valence `0.2`로 약하게 반영합니다.

이 정책은 `놀람`을 `기쁨`과 같은 강한 긍정으로 다루지 않기 위한 안전장치입니다.

### 선호 카테고리

사용자가 자주 기록한 카테고리는 명시적 평점이 없어도 개인 취향을 추정할 수 있는 신호입니다. 다만 감정 기반 서비스에서는 카테고리 취향만으로 추천이 고정되지 않도록, 장소 긍정 비율보다 낮은 가중치를 둡니다.

### 스크랩 신호

스크랩은 사용자의 명시적 관심에 가까운 신호입니다. 다만 스크랩한 장소만 계속 상위에 노출되면 추천 다양성이 줄어들 수 있어 보너스 성격의 낮은 가중치로 반영합니다.

### 소셜 신호

팔로우한 사용자의 긍정 반응은 신뢰 가능한 약한 추천 신호입니다. 하지만 친구 관계가 취향 일치를 보장하지는 않으므로 보조 항목으로 사용합니다.

## 현재 한계

현재 점수식은 다음 한계를 가집니다.

- 실제 사용자 클릭, 방문, 스크랩 전환율로 검증된 가중치가 아니다.
- 각 항목의 상호작용을 학습하지 않는다.
- 후보 생성 단계와 랭킹 단계를 분리한 완전한 추천 시스템은 아니다.
- 위치 거리, 영업 시간, 혼잡도 같은 실제 장소 추천 요소가 아직 없다.
- 정규화 점수는 요청 내부 비교용이므로 서로 다른 요청의 점수를 직접 비교하기 어렵다.

## 포트폴리오에서의 설명 방식

가장 안전한 설명은 다음과 같습니다.

> 추천 로직은 사용자 로그가 충분하지 않은 초기 서비스 상황을 가정한 해석 가능한 baseline ranking으로 설계했다. 장소의 긍정 감정 비율, 최근 감정, 선호 카테고리, 스크랩, 팔로우 사용자의 긍정 반응을 선형 결합했고, DB/MQ 없이도 순수 함수와 샘플 payload 기반 테스트로 정책이 의도대로 동작하는지 검증했다. 이후 실제 클릭/스크랩 로그가 쌓이면 이 가중치는 오프라인 평가를 통해 조정하거나 학습 기반 랭킹 모델로 교체할 수 있다.

## 다음 검증 방향

1. 샘플 시나리오 테스트를 계속 확장한다.
2. 실제 로그가 있다면 클릭/스크랩 여부를 정답 신호로 두고 NDCG, MRR, Precision@K 같은 랭킹 지표를 계산한다.
3. 가중치 조합을 grid search로 비교한다.
4. 충분한 데이터가 생기면 LightGBM ranker나 learning-to-rank 방식으로 교체 가능한 구조를 검토한다.

## 감정 신뢰도 반영 정책

감정 분석 모델은 GPT 합성 데이터로 학습된 baseline이므로, 추천 로직이 감정 예측을 항상 강하게 믿으면 안 됩니다.

backend가 `recentEmotion`에 다음 필드를 전달할 수 있으면 추천 worker는 이를 보수적으로 해석합니다.

```json
{
  "recentEmotion": {
    "emotionLabel": "불안",
    "emotionScore": 0.41,
    "safeLabel": "unknown",
    "isReliable": false
  }
}
```

처리 기준:

- `safeLabel = unknown`이면 최근 감정 라벨을 추천 계산에서 직접 사용하지 않습니다.
- `isReliable = false`이면 감정 점수의 가중치를 기본값의 25%로 낮춥니다.
- 줄어든 감정 가중치는 장소 긍정 비율, 선호 카테고리, 스크랩, 소셜 신호 쪽으로 분산합니다.
- 디버그 응답에는 `emotion_reliable`과 실제 적용된 `w_emo`를 남겨 정책이 적용되었는지 확인할 수 있게 했습니다.

이 정책의 목적은 모델의 낮은 confidence 예측이 추천 결과를 과도하게 흔들지 않도록 하는 것입니다. 모델 교체 전에도 합성 데이터 기반 baseline의 위험을 시스템 차원에서 줄이는 보수 장치로 볼 수 있습니다.
