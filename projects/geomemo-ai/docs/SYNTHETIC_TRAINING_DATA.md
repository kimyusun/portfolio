# 합성 학습 데이터 사용에 대한 기록

## 배경

GeoMemo-AI의 감정 분석 모델은 프로젝트 당시 서비스 도메인에 딱 맞는 공개 한국어 감정 데이터셋을 구하기 어려워, GPT로 생성한 합성 문장을 학습 데이터에 포함해 만들었습니다.

이 선택은 당시 프로젝트를 완성하기 위한 현실적인 방법이었지만, 포트폴리오로 발전시키는 지금은 반드시 한계와 검증 계획을 함께 기록해야 합니다.

## 왜 이 점이 중요한가

합성 데이터로 학습한 모델은 로컬 평가 점수가 높게 나와도 다음 문제가 있을 수 있습니다.

- 학습 데이터와 평가 데이터가 비슷한 생성 방식이면 점수가 과대평가될 수 있습니다.
- 실제 사용자의 짧고 불완전한 메모 문장에 대한 일반화 성능은 별도로 확인해야 합니다.
- GPT가 만든 문장은 감정 표현이 비교적 명확할 수 있어, 애매한 실제 문장을 충분히 반영하지 못할 수 있습니다.
- `놀람`, `상처`, `불안`처럼 문맥 의존적인 라벨은 합성 데이터에서 경계가 인위적으로 깔끔해질 수 있습니다.
- confidence score가 높아도 실제 도메인에서는 틀릴 수 있습니다.

따라서 기존 평가 결과인 6-class Macro-F1 약 `0.9020`은 “현재 baseline이 학습/평가 세트 안에서 잘 작동했다”는 근거로만 사용하고, 실제 도메인 성능의 최종 증거로 말하지 않습니다.

## 포트폴리오에서 숨기지 말아야 할 점

이 프로젝트를 설명할 때는 다음처럼 말하는 것이 안전합니다.

> 프로젝트 당시에는 서비스 도메인에 맞는 공개 한국어 감정 데이터셋을 확보하기 어려워 GPT로 생성한 합성 데이터를 활용해 baseline 감정 모델을 만들었다. 이 때문에 로컬 평가 성능이 높더라도 실제 사용자 메모에 대한 일반화 성능은 별도 검증이 필요하다고 판단했다. 포트폴리오 정리 과정에서는 이 한계를 숨기지 않고, 도메인 평가셋과 에러 분석 표를 설계해 모델 업그레이드 여부를 판단할 수 있는 구조로 발전시켰다.

## 현재 모델을 어떻게 봐야 하는가

현재 모델은 “완성된 최종 감정 모델”이라기보다 다음 성격의 baseline입니다.

- 팀 프로젝트에서 end-to-end AI worker 흐름을 구현하기 위한 baseline
- 감정 라벨 체계와 추천/인사이트 연동을 검증하기 위한 baseline
- 이후 실제 도메인 데이터로 재평가하고 개선할 출발점

## 개선 방향

### 1. 도메인 평가셋을 별도로 만든다

합성 학습 데이터와 독립적인 평가셋이 필요합니다.

- 실제 사용자가 쓸 법한 짧은 메모 문장
- 라벨별 최소 30~50개 문장
- `놀람`은 긍정/중립/부정 문맥을 나눠 기록
- 모호한 문장은 `memo`에 라벨링 이유를 남김

현재 샘플은 `data/sample_emotion_domain_eval.csv`에 있습니다.

### 2. 에러 분석을 먼저 한다

모델을 바로 교체하기 전에 어떤 문제가 있는지 확인합니다.

- 라벨 혼동
- 문맥 부족
- 반어/비꼼
- 여러 감정이 섞인 문장
- confidence가 높은 오답
- `놀람`의 valence 판단 오류

### 3. 업그레이드 여부를 판단한다

도메인 평가셋에서 문제가 확인되면 다음 순서로 개선합니다.

1. confidence threshold 또는 `unknown` 처리
2. `놀람` 같은 문맥 의존 라벨의 정책 보정
3. 실제/검수 데이터로 추가 fine-tuning
4. 다른 한국어 감정 분류 모델과 비교

## 면접 답변 포인트

좋은 답변은 “GPT 데이터로 만들었지만 성능이 높았다”가 아닙니다.

더 좋은 답변은 다음입니다.

> 당시에는 데이터 확보가 어려워 GPT 합성 데이터로 baseline을 만들었지만, 합성 데이터 기반 평가가 실제 사용자 문장 성능을 보장하지 않는다는 점을 인식했다. 그래서 포트폴리오 정리 과정에서 모델을 무작정 교체하기보다, 도메인 평가셋과 에러 분석 체계를 먼저 만들고 모델 개선 여부를 판단하는 방향으로 발전시켰다.
